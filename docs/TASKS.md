# North16 benchmark protocol 草案 design-v0.7

本文件给出预期冻结的规范。标签类别、主要指标和泄漏规则可以先确定；时区、映射关系、配准容差、SAR 时间窗、独立场景划分必须通过 pilot 后冻结。所有尚未达到门槛的任务标记为 planned，不以已完成 benchmark 对外宣称。

本协议适用于经受支持适配器导入的全部会话/日期，统一构建方案见 BUILD.md。原始目录格式由 adapter 描述，导入路径与会话归属由 import 配置描述，不为每一天另改标签和评测规则。源文件组织变化只更新 adapter；任务定义、属性判据或评测规则变化则增加 protocol 版本。新增数据不自动重划已有 release 的训练/测试集合。

## 1. 任务登记与公平比较

| Task ID | 输入 | 输出/标签坐标系 | 发布门槛 |
| --- | --- | --- | --- |
| SEG-VIS | 一张原始可见光图像 | 本图像 sky/water/ice/other 四类 mask | 标注与 QC、独立场景划分完成 |
| SEG-IR | 一张红外视频解码图像 | 本图像 sky/water/ice/other 四类 mask | 同上；明确其非辐射测温数据 |
| SEG-ICE-RADAR | 一份独立冰雷达扫描 | 本雷达图像内 water/ice/other；无效或不可辨认处 ignore | 专家确认海冰/水可辨识与可标注性；无回波不自动标为水 |
| DET-VIS / DET-IR | 一张本模态图像 | 本模态 ship 检测框 | 足够独立遭遇事件、全图穷尽标注及负样本 |
| DET-RADAR | 真实雷达回波/图像 | 明确定义的 ship echo 框或地理目标 | 导航雷达图像到位，几何与标注可验证；不能把导航文本当图像 |
| FUSION-SEG / FUSION-DET | 已登记的传感器组合与缺失 mask | 明确一个 reference sensor 的 mask/框 | 时间误差、视场重叠、配准误差及标签可用性通过验收 |
| SAR-SEG / SAR-DET | 独立 SAR 产品的地理图块 | 本 SAR 网格的 mask/框/可选旋转框 | 产品预处理、独立 SAR 标签和独立场景数足够 |
| ASYNC-SAR-CONTEXT | 船载输入 + 时空关联 SAR + age/导航元数据 | reference 船载传感器的 mask/框 | 已冻结 offline 或 causal 设置，多独立 SAR 产品和无产品泄漏的划分 |

每条成绩明确 task_id、protocol_version、split_version、label_version、input_modalities、target_sensor、预训练/外部数据、时间设置和模态缺失策略。传感器组合不同单独列成绩；单模态与融合的公平增益比较必须使用同一 reference 标签与同一测试子集，同时报告全量单模态测试结果及配对覆盖率。

语义分割与检测可以联合训练，但必须分别报告；不得把像素分割 mIoU 和检测 AP 简单平均成一个总榜。雷达回波目标与相机可见船体的观测含义不同，标签不直接互换。

## 2. 分割标注手册

第一版可见光/红外采用**天空、水、冰、其他四类语义分割**，不要求区分每块浮冰实例或细分冰型。气象条件与白昼/夜间作为独立场景属性保存，不加入像素类别。标签 PNG 为单通道 uint8，尺寸等于源观测：

| ID | 类别 | 标注规则 |
| --- | --- | --- |
| 0 | sky | 天空及其中的云；地平线沿可辨识边界标注 |
| 1 | water | 可判定的开阔水面、冰间水道；可判明属于水面的浪花/反光归 water |
| 2 | ice | 可辨识海冰与冰上积雪；融池若明确位于冰面内，按冰的承载表面归 ice |
| 3 | other | 可辨识且不属于前三类的实体，例如本船/其他船舶、陆地、设备 |
| 255 | ignore | 无效范围、NoData、完全遮挡或无法可靠判定的像素；不参与损失和指标计算 |

“其他”是正常参与训练和评测的第四类，“无法判断”单独用 ignore。可见船体等遮挡物标 other，无法看到的被遮挡海面不推断标签。ignore_reason 可保留 invalid_sensor、uncertain_boundary、unidentifiable_surface，避免为了提高模型成绩扩大 ignore。船舶在分割 mask 中归 other，在检测任务中仍单独标 ship 框。雷达/SAR 没有天空，沿用 water=1、ice=2、other=3、ignore=255，并只评测适用类别；other 的模态专用判据需专家确认，雷达盲区与阴影不能直接归 other。

具体约定：

1. 碎冰尽量沿可见轮廓标出，冰间可辨认水面保留。分辨率不足的混合像素按手册指定的可辨识边界处理，不凭空细化；试标后制作至少 20 个边界实例示范并冻结。
2. 薄冰/新生冰只在本任务允许的证据下能确认时标 ice；否则 uncertain，不把暗色统一当水。IR 中热对比不能直接等同物理类别。
3. 不能辨认的炫光、浓雾、强噪声与完全遮挡区域标 ignore；可以判定的困难区域正常标注。气象与光照按下节登记，额外难度标签可选。记录每帧有效标注面积及不确定比例。
4. 雷达低回波/阴影/盲区不默认 water；保留近场盲区、量程外、扇区缺失和地理 NoData。雷达海冰类别必须由专家制定模态专用判据；若只能可靠标注回波区，应另定义“回波分割”，不能冒充海冰真值。
5. mask 必须在原图坐标系精修；预览可缩放、增强，但保存映射参数。任何传感器到另一传感器的标签传播均是草稿，未经配准验证与人工复核不能成为 test gold。

标注证据设置必须分开：`native-only` 仅看目标图像；`multi-evidence` 可以看配对模态/邻帧/专家材料，每个标签记录实际使用的证据 ID。若测试 gold 利用其他模态，不能再声称标注员间一致性代表单模态可辨识上限；应单独报告目标模态可观测性与歧义子集。

建议在本地 CVAT/同类工具保留多边形/brush 工程，统一导出 PNG 和 provenance。模型预标注后逐图人工修订；test 至少包含一批独立人工复标样本，记录模型来源及可能的自动化偏差。划分冻结后不得用 test 标签训练预标注模型或修改训练选择规则。

### 2.1 气象条件与光照时段

两个属性独立存储，不合成一个混杂类别。按条件连续的航段标注，条件变化时细分或逐帧覆盖；每条保留 evidence_source、evidence_id、confidence 及需要时的 unknown_reason。unknown 是元数据缺失/判定状态，不是额外像素类，不用于四类分割训练。

文件夹中采用片段 info.txt 保存有共同证据的天气/光照默认属性，相机目录 info.txt 保存设备与源视频信息，meta/<frame_stem>.txt 保存逐帧信息及覆盖项。各属性分别使用 weather_*、illumination_* 来源/证据/审核字段；固定字段和继承规则见 METADATA.md。分割 mask 仍是单通道 PNG，放在 masks/；标签版本在数据集 info.txt 与发布快照中固定；TXT 不代替像素标签。总索引 samples.txt 是 TXT 元信息解析后自动生成的 TSV 快照，不手工重复维护场景标签。机器入口 protocol.txt 与对应 North16SegDataset 的读取合同见 DATASET.md；它只实现 可见光/红外 分割，非通用融合或官方评测器。

| 属性 | 中文分组 | 标签 | 判定规则 |
| --- | --- | --- | --- |
| 气象条件 | 晴朗 | clear | 晴或少云，无可辨识的雾、雨、雪 |
| 气象条件 | 阴云 | cloudy_overcast | 多云至阴，以云层遮蔽为主，无可辨识的雾、雨、雪 |
| 气象条件 | 雾或降水 | fog_precipitation | 有可靠记录或可辨识的雾、雨、雪；混合天气优先归此组 |
| 光照时段 | 白昼 | day | 优先依据经验证时间与船位计算太阳高度角；协议约定几何太阳中心高度 >=0° |
| 光照时段 | 夜间 | night | 同一计算约定下太阳高度角 <-6° |

这里的天气是面向感知评测的简化分组，不等同标准气象站完整天气编码。夜间气象优先依赖同期气象记录，没有可靠证据时天气填 unknown；图像暗、模糊或镜头水滴不能单独证明阴天、雾或降水。晴朗/阴云边界先用试标示例统一，不能把太阳是否直射当唯一依据。

光照时段采用上述操作定义，太阳高度角 -6° 至 0°（不含 0°）记 illumination=unknown、unknown_reason=twilight，保留原始角度供单独分析；不硬塞进白昼/夜间主比较。该阈值是本协议的晨昏排除规则，不宣称所有夜间照明条件相同。极区不能用固定北京时间/当地钟点划分；若 UTC、日期或船位未验证，则不计算已认证的太阳高度，使用有证据的人工复核并标来源，或保持 unknown。红外画面亮度、船上人工照明和相机自动曝光不改变 day/night 标签。

分别报告三组气象、两组光照下的 Ice IoU、mIoU 与独立航段数；样本充足时补充 3×2 交叉结果。unknown/晨昏样本仍保留在总体任务评测，按原因报告数量，但不混进已确认条件的分组成绩。若某组缺数据，标记缺失，不为了填满表格拆分高度相关帧。场景属性可供数据筛选和分组评测，默认不作为模型输入；使用时在协议中另声明。

## 3. 船舶检测标注手册

第一版仅一个类别 ship，避免在独立船数不足时强行分细类。可见光/红外 先采用原图像水平框，COCO bbox=`[x,y,width,height]`，浮点像素坐标，坐标原点左上角。SAR 若另开旋转框任务，角度方向/范围、顶点顺序、IoU 实现必须单独冻结，水平框与旋转框不共用成绩。

- 标出可见船体及其可辨认船上结构的紧框，不包含尾迹、镜面反射、冰山和自身船舶。遮挡时框定可见部分，记录 occlusion/truncation；只在有明确 amodal 定义的独立任务中推断完整外形。
- 每张入选检测图穷尽标注，保留真实无船负样本。图像尚未审核时 status=unlabeled；审核确认无船时 status=verified_negative，两者不能混淆。
- 极小疑似亮点不直接当船。根据 pilot 制定可确认的最小尺度与 ignore-region 规则，并报告各传感器的小目标分布，不能看测试结果调门槛。
- 船舶的跨帧、跨镜头 identity 记录为 encounter_id/track_id；暂不能确认对应时不强行赋同一 ID。用身份/遭遇分组防止同一事件散入训练与测试，数量不足时明确仅为同船/同日设置。
- AIS、导航雷达目标列表或 KML 中目标记录只提供关联证据；检查时间、位置、可见性和目标身份后才能用于图像标签。AIS 不发射、信号缺失或未匹配不能当作没有船。
- 雷达 ghost、旁瓣、海杂波与真实船舶回波的区分，需模态专用手册和专家仲裁；若真值不足，该任务保持 planned。

COCO 原生 crowd/ignore 机制不能直接代替任意“疑似区域”定义。官方检测导出额外保存 regions.json。评测器应先执行正常 GT 匹配，再对未匹配预测按已冻结规则处理 ignore region，例如 bbox 面积与 ignore 多边形相交比例 >=0.5 的预测不计 FP；其余按正常 FP 计算。该扩展需明确命名为 COCO-style with ignore regions；纯 COCO 对照子集单列，不能隐去协议差异。

## 4. 标注质量控制

工作流：培训与试标 → 初标 → 复核 → 分歧仲裁 → 自动格式检查 → 锁定。每张记录 annotator、reviewer、工具/模型、耗时、证据范围、revision 和 status；未经复核不能进入发布 gold。

建议 pilot 全部双标；规模扩大后 train/val 至少随机分层抽 10% 双标并覆盖困难情况，test 全部独立复核、至少 20% 独立双标。比例为草案预算，按实际专家成本在发布前冻结；复核和独立双标分别统计，不能混为一项。

报告类别 IoU/边界分歧、有效域分歧、检测框匹配 IoU、遗漏/误标率；分歧指标在双方可比较区域上计算，并单独报告 ignore 不一致。pilot 形成“可接受门槛、返工条件、仲裁流程”后再扩标，当前没有一致性实测结果。

自动验收：mask 值域/尺寸、未知类别、空有效域、检测框越界/重复、重复源观测重复计数、标注证据缺失、train/test 来源冲突。抽样人工验收困难区域和真实负样本，禁止只检查模型表现好的样本。

## 5. 防止泄漏的数据划分

优先级：独立航次 → 独立日期 → 空间航段/场景；不能逐帧随机划分。目录切段边界不代表场景边界。建立 group_id，把以下关系的连通分量作为不能跨 split 的组：

1. 同一连续海况/空间相邻且相关的航段及相邻时间上下文；相机多镜头、IR、雷达同一物理事件。
2. 相同源帧的裁剪/增强/重投影、完全重复或确认近重复图像、同一独立雷达扫描的重复保存。
3. 同一船舶遭遇事件；若发布 unseen-vessel 测试，物理船舶 identity 也必须隔离。
4. 同一 SAR product/source scene、重叠瓦片、相邻轨道产品中相同地面覆盖的关联关系。所有由该 SAR 辅助的船载样本跟随同组；不能只检查 SAR 文件名不同。

在组级提出约 70/15/15 train/val/test 目标，再检查独立场景数、类别、船舶遭遇及难度覆盖；比例服从真实独立性，组数太少不硬拆。相邻组加时间/空间隔离带，距离由场景持续性和上下文窗口确定，至少覆盖算法允许的完整上下文，不用任意固定秒数冒充独立性。

当前仅审计了一个日期：可建立开发用 blocked split 并声明同日限制；正式跨日主榜至少要有可分开的独立日期/航次组，样本数由统计与覆盖决定。若全日只用同一 SAR 产品，严格按产品划分时该日会成为一个组，不能同时落入 train/val/test；需要更多日/产品，或另设 SAR 不参与输入的单模态划分。

测试清单只公开输入及必要元数据，gold 存放在发布目录之外。若一份图像在任何其他任务中属于受保护 test，相同或可直接传播的标签不能作为另一任务公开 train 标签；跨任务联合训练使用统一 source group 的训练资格清单。非受保护的单独公开研究版本可以提供全部标签，但必须与隐藏测试榜区分。

半监督/自监督设置单列：默认 closed setting 只用 train 组内未标注原始数据；test 时段/日期的未标注视频、SAR 产品及其派生物不能混入预训练。若允许 transductive 使用，应建立独立协议与榜单。

## 6. 固定评测

| 任务 | 主指标 | 辅指标 |
| --- | --- | --- |
| 可见光/红外海冰分割 | scene-macro mIoU（sky/water/ice/other 四类） | 全局 mIoU、逐类 IoU、Ice IoU/Dice、water/ice mIoU、Boundary F1、有效像素覆盖率 |
| 雷达/SAR 分割 | 适用类别上的 scene-macro mIoU（water/ice/other） | 逐类 IoU、Ice IoU/Dice、water/ice mIoU、有效像素覆盖率；类别可辨识性需先验证 |
| 图像船舶检测 | COCO-style AP@[.50:.05:.95] | AP50、AP75、APsmall/medium/large、AR100、按独立遭遇事件分层分析 |
| SAR 上下文辅助 | 与 reference 任务相同 | 同测试样本的无 SAR 对照；按 SAR age、覆盖和配准质量分层 |
| 计算效率 | 不与精度混成单值 | 相同硬件的参数量、显存、延迟分位数、端到端吞吐与输入预处理成本 |

分割：对每个独立 scene 累积有效像素混淆矩阵，`IoU_c=TP_c/(TP_c+FP_c+FN_c)`；在该 scene union>0 的类别上平均，再对 scene 等权平均。整个 scene 无有效像素不应出现在冻结测试清单；出现时验证失败。全局 mIoU 另汇总全部像素，防止长视频/大视场主导唯一主指标。Ice Dice 使用明确的全局或 scene 汇总，报告约定；无冰且无预测冰的空类不自动赠送满分，记录为空并报告空类场景表现。

四类任务的混淆矩阵包含 sky、water、ice、other，255 排除。辅助 water/ice mIoU 从同一完整混淆矩阵提取两类 IoU 后平均，保留冰/水与天空/其他之间的误分类惩罚，不按 GT 只裁出海面来消除这些错误。主榜同时突出 Ice IoU，便于判断实际海冰分割效果。各任务的类别集合与预测值域在任务清单中冻结，融合任务遵循 reference sensor 的类别集合。

Boundary F1：回到源图网格，在有效域内计算 ice/water 边界；草案容差 `ceil(0.002 * sqrt(H^2+W^2))` 像素，避开 ignore 边界同宽带，不把有效域边缘当作类别边界。无 GT 和预测边界的 scene 对边界指标记 NA，单边存在记 0，同时报告参与 scene 数。该指标是本 benchmark 自定义，不暗称通用唯一标准。

检测：固定 pycocotools 版本、bbox 评测、IoU 0.50:0.05:0.95、101 recall 点、maxDets=[1,10,100]；AP 汇总为 0—100。面积区间按原图坐标和冻结 annotation.area（bbox-only 时为 w×h）计算。推理 resize 后映射回原图；分辨率与面积分布按传感器分别报告。ignore 扩展及难例规则按第 3 节固定。某测试分组无任何 ship GT 时 AP 记 NA，另报 FP/image，不把它当完美检测。

对照模型使用相同 split、输入资格、标签版本与参考测试清单；训练增强和推理策略公开。归一化统计只从 train 拟合。固定多种子例如 [17,42,2026]，报告均值和标准差；置信区间按独立 scene/日期/船舶遭遇或 SAR 产品组 bootstrap，不能对高度相关连续帧假定独立。独立组不足时给出区间限制，不能用更多帧制造显著性。

预测缺失、重复、尺寸不符、未知 ID、类别非法直接判提交无效；不自动跳过失败样本。空预测对有 GT 的图像按正常失败计分。阈值/后处理只在 val 调整，test 仅作最终冻结评估。

## 7. 多模态与时序专用约定

每个融合任务明确：reference sensor、输入组合、匹配容差、可用时窗、外参与映射版本、空间覆盖、valid-overlap、缺失编码、标签证据。仅有时间关联时可用独立编码器/事件级特征融合，不将其包装成已配准的像素融合。

主比较包含相同预算的单模态、简单 late fusion、具备有效空间依据时的 early fusion，以及候选高级模型。至少验证：模态增益、时间偏移、配准误差、随机/整段模态缺失、雷达陈旧扫描和 SAR age。合成扰动在固定测试输入上按预定义规则生成，不能改变 gold。

时间上下文另开 causal 与 offline 两套。causal 在时刻 t 仅用采集及可用时间 <=t 的观测；雷达扫描需等其允许的扫描完成时间，SAR 还需满足产品到达时间。offline 若使用未来帧或未来 SAR 必须声明，不能放进实时感知主榜。

已有数据视频约 1 Hz，时序任务名称/速度结论必须反映实际采样频率；不能插帧后宣称更高真实观测帧率。

## 9. 发布与版本

发布物包括：dataset card、传感器布局/标定、时间关联说明、独立性统计、标注手册、输入与标签 schema、固定 split、验证工具、官方 evaluator、代表基线配置/权重/日志、环境锁定、SHA-256、已知缺陷、数据与代码许可。来源再分发和 SAR 产品许可在数据卡中分别记录。

数据 release、label、split、protocol、converter 独立编号；修复影响标签或测试样本时必须增加版本并重跑基线，旧版成绩保留版本标识。修复时钟后不改变 observation_id，但重新生成关联、任务清单与受影响的 split/成绩。记录变更理由和可追溯来源。

所有“首个”“更准确”“跨区域有效”“像素级同步”等主张，分别需要文献检索、真实评测、留出域实证或对齐验证。本设计尚未产生实验结果。


## 10. 场景映射与汇总补充（design-v0.7）

正式 scene-macro 使用 splits/scenes.txt 中冻结的 id/scene_id/group 映射；scene 由物理场景审核得到，不以存储 sequence 自动代替。group 用于来源隔离，可以包含多个 scene。评测映射、frame meta 和样本 group 不一致时验收失败。

全局 IoU 及 Ice Dice 从同一完整有效域混淆矩阵计算；Ice Dice 主报告为全局 2TP/(2TP+FP+FN)，scene-macro Dice 可补充单列。某类别在全局 GT 与预测均不存在时记 NA，并从类别均值排除，报告参与类别；scene 空类规则见第 6 节。所有分割指标报告为 0—100%，不能混用小数与百分数。Boundary F1 为补充指标，正式发布前须实现并通过参考样例校验，不作为首次试点完成条件。
