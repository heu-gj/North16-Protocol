# 0.6.0 构建流程

当前规范以[初始化、相机、分割模块](MODULES.md)为准：初始化不抽帧、不创建masks；相机模块独立处理；分割默认导出同结构masks/*.json；整包合并后Dataset直接读取。下方保留旧版接口与历史实现说明，仅用于兼容和追溯。

# 构建与预处理协议

修订：design-v0.7。显式单根/片段的相机试点转换已实现；通用发现与其他任务阶段尚未全部实现。以下为统一合同，具体已实现范围见 EXECUTION.md。

## 1. 配置职责与预检

protocol.yaml 保存跨批次规则；import/pilot YAML 保存本次输入、来源会话、输出与运行参数；adapter YAML 保存源布局映射。引用相对于包含引用的 YAML 解析，不能依赖运行终端的 cwd。先校验配置/schema/枚举/必需门槛，再发现资产。

原始根只读，输出不得位于任何原始根内。发现只接受受支持签名，排除输出和已登记路径别名。未知流登记 unrecognized，不猜类型。处理前检查权限、解码依赖、目标空间和容量估算；不因缺少可选 SAR 阻断相机任务。

## 2. 稳定身份与命名

片段名称例如 2026_09_02_04_42_32_data 映射为 sequence=20260902_044232，仅代表源标签，不认证 UTC。身份登记键为 source_namespace + session_id + 源相对路径，源资产登记 source_id、raw_root_id、SHA-256 和大小。不能用发现顺序或文件修改时间做身份。

同一已登记来源重复出现应复用 source_id；同路径内容变化必须报冲突并登记新资产修订，不能静默替换。跨来源的同内容哈希用于去重候选，不自动合并物理观测。sequence 重名时保留已登记名称，为新来源添加基于已登记来源身份的稳定短后缀；后缀碰撞必须延长或报错，不按执行次序编号。

根 info.txt 的 source_registry 指向最后成功提交的 logs/<run_id>/sources.txt。每次运行加载此前完整来源快照，登记后生成新的完整快照并最后原子更新该引用；恢复时不得仅凭当前目录重新发号。首次无登记时为 unknown。session_id 是人工登记的来源会话身份，不自动等同独立航次或场景。

camera 使用 front_01/back_01 等；模态使用 visible/infrared；各视频按解码输出次序命名 f000000.png 起。全局 id 示例为 n16_20260902_044232_visible_front_01_f000000。真实唯一性由源登记与 observation 映射保证；修订时钟不改变观测 ID。解码配置改变导致帧/像素变化时必须新数据修订，不能覆盖原有观测。

## 3. 阶段顺序与产物

| 阶段 | 输入 | 输出与通过条件 |
| --- | --- | --- |
| inspect | 任务、适配器、原始文件 | sources/steps/errors、实际流清单、帧/日志探测、容量估算 |
| extract | 已通过预检的资产 | 全部实际解码图像、meta、扫描/接收和导航记录、数量对账 |
| index | 观测与已审核属性 | 解析继承后的 samples.txt、来源校验与数据集声明 |
| associate | 观测、时钟/标定证据 | pairs/sar_links 和关系证据；未解决留候选 |
| sample | 观测、分组提案、选择规则 | candidates.txt 与原因；选择只改变候选，不删除源图 |
| annotate | 候选、工具导出、人工证据 | mask/检测标注、review、history；完成后重建索引 |
| split | 独立场景与共享来源关系 | 固定 train/val/test、scenes.txt、排除原因 |
| validate | 对应阶段的资产与规则 | checks.txt，按检查范围分 pass/fail/not_checked/not_applicable |
| release | 已通过全部启用任务验收的工作集 | 新目录冻结快照、版本/校验和、公开标签剥离检查 |

每阶段都先执行其前置校验；validate 可独立用于任意阶段。时间审计贯穿 inspect 和 associate，不要求认证时钟后才允许抽取单模态图像。人工修改后重新 index/validate，不能训练时动态解析变化中的人工记录。试点停在检查/试标，不进入 split/release。

## 4. 相机预处理

提取全部实际可解码源帧，原尺寸 PNG，无增强、不裁剪、不去雾、不按固定 FPS 插删帧。保存 PTS、time_base、解码序号、日志行候选、像素格式/色彩转换配置与软件构建。容器标称帧数、探测帧条目数、成功输出数与失败数分别统计，不能假设彼此相等。

解码器可变帧率/帧重排按实际记录；PTS 缺失或不连续时不推算伪时间。读取错误保存位置和原因，无法定位未解码帧时如实记 unknown，不伪造一一对账。

PNG 只避免新增有损压缩，不能恢复源压缩损失。红外为视频显示强度，不宣称辐射温度；未来 radiometric 原始量另存并定义专用处理。当前训练 reader 支持 8-bit RGB/L 图像，颜色转换配置在正式转换前固定。

## 5. 时间、配准与其他传感器

原始时间字段与日志原件保留。未经证明不能将帧与日志按行 zip，不能把片段起始时间 + 序号/FPS 当认证采集时间。时钟模型需登记来源、有效范围、时区/日期、漂移、重启和误差；验证后才赋 capture_time_utc。未解决时间不阻断单模态标注。

关联用经验证时钟、真实差值和不确定度；阈值为 null 时不得产生正式融合资格。时间状态与空间状态分开；仅事件关联不复制 mask、不直接多通道拼接。每个融合任务明确 reference、重叠区、配准版本及缺失策略。

雷达保留原始 GeoTIFF/KML/index、CRS、NoData、仿射和位深；哈希和元数据检测重复，接收记录多行可引用同一扫描。不同哈希不等于独立扫描。KML 修复另存派生版本，记录原件与规则，不改原件。

导航文本放 nav；未确认导出语义不把 GGA-like 坐标和 TIME 直接认证为轨迹。nav_radar 只有实际图像才生成。SAR 一产品一份，登记真实过境/覆盖/可用时间，按产品物理量配置校准和地理处理，不对所有产品套同一链。每日日期不能代替配对证据。

所有增强、重投影、裁剪和标注预览均是派生物，记录输入哈希、配置、输出网格和变换关系，不能覆盖标准观测。默认单模态主任务只读 images 中的原尺寸解码图。

## 6. 人工记录与候选管理

sequence/info.txt 和 frame meta 中人工审核的属性、mask 与原始标注工程必须保留。相机全部观测进入 samples；候选清单写入运行 candidates.txt，携带选择方法、条件和理由。首试 30—60 张，其他扩标任务自行声明预算，不将其硬编码为协议总配额。

labels 状态按 TASKS.md 复核推进；返工时工作副本退回 draft 并保存历史，旧 frozen 快照不修改。没有 mask 时样本表路径留空；已标注后填真实相对路径。属性继承由构建器成组解析，不能只继承类别却丢失证据。

## 7. 恢复、冲突与更新

每次运行生成 run_id，保存解析后的完整配置快照、配置哈希、协议/软件版本、明确源范围和命令参数。阶段记录 running 后再写数据；每个资产先写临时文件，验收后原子提交。快照索引最后切换，防止读到一半新数据。

重跑先比较来源身份、输入/转换配置和输出校验和；同资产同参数且结果完整可复用。不同内容、配置或人工记录冲突必须停止受影响资产；禁止 overwrite=true 覆盖。resume 只恢复已验收产物，崩溃临时文件不能视为完成。

新增日期不重排已冻结 split；新关联把旧 train/test 连通时必须报冲突，修订 split/release 后处理。修时钟重建关联与受影响索引/划分，不重命名源观测。更新仅在未使用的工作集进行，训练绑定独立冻结快照。

## 8. 日志与最终资格

每次运行保存 info.txt、sources.txt、steps.txt、errors.txt、checks.txt；实际启用候选选择时另有 candidates.txt。结构见 METADATA.md，模板见 ../templates/txt/。失败错误对应资产/阶段/check，不用“程序返回 0”代替质量验收。

资产问题只阻断依赖它的阶段；缺少同步证据将融合阶段 blocked，不把已成功的相机提取判成同步成功。整次运行只在所声明范围的检查全部成功时 succeeded，有失败/阻塞必须显式报告。人工步骤 pending 时不能将全流程标成完成。

首试具体输入与门槛见 PILOT.md；发布前还须按 TASKS.md 冻结标签质量、场景划分、指标、环境及许可。
